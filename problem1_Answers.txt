Q1.1 Insert a row in the DEPARTMENT table that references a row in the EMPLOYEE 
     table. Then try to delete the referenced row. What will happen?
--------------------------------------------------------------------------------

[SQL Used]
-- Step 1: Ensure an employee exists
INSERT INTO EMPLOYEE (ssn, fname, lname, bdate, address, gender, salary, Dno)
VALUES (104, 'Tarek', 'Mahmoud', '1995-02-10', 'Alexandria', 'M', 12000.00, NULL);

-- Step 2: Insert a department that references employee 104 as manager
INSERT INTO DEPARTMENT (Dnumber, Dname, mgr_ssn, mgr_start_date)
VALUES (4, 'Human Resources', 104, '2022-01-01');

-- Step 3: Try to delete the referenced employee row
DELETE FROM EMPLOYEE WHERE ssn = 104;

[Output / Error]
ERROR 1451 (23000): Cannot delete or update a parent row: a foreign key constraint fails (`company`.`department`, CONSTRAINT `department_ibfk_1` FOREIGN KEY (`mgr_ssn`) REFERENCES `employee` (`ssn`))

[Explanation]
MySQL enforces referential integrity. Because DEPARTMENT has a foreign key constraint (mgr_ssn) referencing EMPLOYEE(ssn) with the default RESTRICT / NO ACTION rule, MySQL prevents deleting the parent record in EMPLOYEE as long as child records in DEPARTMENT still refer to it.

Q1.2 Insert a row in the PROJECT table that references a row in the DEPARTMENT 
     table that doesn't exist yet. What will happen?
--------------------------------------------------------------------------------

[SQL Used]
-- Attempt to insert a project referencing non-existent department 999:
INSERT INTO PROJECT (Pnumber, Pname, Plocation, Dno)
VALUES (99, 'NextGen Satellite', 'Aswan', 999);

[Output / Error]
ERROR 1452 (23000): Cannot add or update a child row: a foreign key constraint fails (`company`.`project`, CONSTRAINT `project_ibfk_1` FOREIGN KEY (`Dno`) REFERENCES `department` (`Dnumber`))

[Explanation]
Referential integrity requires that foreign key values must either be NULL (if permitted) or correspond to an existing primary key value in the referenced parent table. Since department 999 does not exist in the DEPARTMENT table, the foreign key check fails and MySQL rejects the INSERT.

Q1.3 If mgr_ssn and Dno are both NOT NULL, how will you insert the first row in 
     EMPLOYEE or DEPARTMENT?
--------------------------------------------------------------------------------

[SQL / Solution]
When both foreign keys (DEPARTMENT.mgr_ssn and EMPLOYEE.Dno) are declared NOT NULL, a circular dependency occurs:
- An EMPLOYEE cannot be inserted without an existing DEPARTMENT(Dnumber).
- A DEPARTMENT cannot be inserted without an existing EMPLOYEE(ssn).
Neither table can accept the first record while foreign key checks are active.

In MySQL, the standard way to resolve this is to temporarily disable foreign key checks, insert the mutually-dependent rows, and then re-enable foreign key checks:

-- Step 1: Temporarily disable foreign key constraint enforcement
SET FOREIGN_KEY_CHECKS = 0;

-- Step 2: Insert the first employee referencing Department 1
INSERT INTO EMPLOYEE (ssn, fname, lname, bdate, address, gender, salary, Dno)
VALUES (1, 'Khaled', 'Nabil', '1991-04-12', 'Sidi Gaber, Alexandria', 'M', 18000.00, 1);

-- Step 3: Insert the first department referencing Employee 1 as manager
INSERT INTO DEPARTMENT (Dnumber, Dname, mgr_ssn, mgr_start_date)
VALUES (1, 'Headquarters', 1, '2020-01-01');

-- Step 4: Re-enable foreign key checks
SET FOREIGN_KEY_CHECKS = 1;

[Alternative DDL Solution]
Alternatively, define the schema by creating both tables without one of the foreign keys (e.g., without the foreign key on EMPLOYEE.Dno), insert the initial data, and then execute an ALTER TABLE statement to add the NOT NULL foreign key constraint:
ALTER TABLE EMPLOYEE ADD FOREIGN KEY (Dno) REFERENCES DEPARTMENT(Dnumber);
